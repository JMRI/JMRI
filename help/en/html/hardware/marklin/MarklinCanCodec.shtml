Märklin CAN Codec Library Implementation

This page describes the JMRI Märklin CAN (MCAN) codec library implementation. Please also read the Javadocs for the jmrix.marklin package.

Overview

The MarklinCanCodec class encodes and decodes Märklin CAN (MCAN) frames for the adapter, monitor, throttle, turnout and standalone bridge.

Why a separate library?

Frame encoding and decoding are centralized in MarklinCanCodec so the adapter and standalone tools use the same frame format. The codec is tested independently of Swing and TrafficController.

MarklinCanCodec API

The API consists of a decoded-message value, a message builder and utility methods.

1. DecodedMessage Class

An immutable data structure representing a fully decoded MCAN message:

MarklinCanCodec.DecodedMessage decoded = MarklinCanCodec.decode(rawMessage);

// Access decoded fields with type-safe methods
int priority = decoded.getPriority();
int command = decoded.getCommand();
boolean isResponse = decoded.isResponse();
long address = decoded.getAddress();
int speed = (decoded.getDataByte(0) << 8) + decoded.getDataByte(1);

2. MessageBuilder Class

A fluent API for constructing encoded messages:

int[] encoded = MarklinCanCodec.builder()
    .setCommand(MarklinConstants.LOCOSPEED)
    .setAddress(0xC003)
    .setData((speed >> 8) & 0xff, speed & 0xff)
    .setDataLength(2)
    .build();

3. Utility Methods

Protocol analysis helpers for common operations:

String priorityDesc = MarklinCanCodec.getPriorityDescription(priority);
String protocol = MarklinCanCodec.getProtocolFromAddress(address);
long baseAddr = MarklinCanCodec.getBaseAddress(address);

MCAN Protocol Structure

The codec handles the 13-byte MCAN message format per the CS2 CAN Protocol 2.0 specification:

Bytes Field Description
0 Priority + Command[14:7] Priority (bits 7-4), Command high bits (bits 3-0)
1 Command[6:0] + Response Command low bits (bits 7-1), Response flag (bit 0)
2-3 Hash 16-bit hash/identifier
4 DLC Data Length Code (0-8 bytes in the CAN payload)
5-8 Address 32-bit CAN address (big-endian)
9-12 Data Data bytes exposed by DecodedMessage.getDataByte(int)

Priority Levels

  • Priority 1 (0x00): Stop/Go/Short messages
  • Priority 2 (0x01): Feedback
  • Priority 3 (0x02): Engine Stop
  • Priority 4 (0x03): Engine/Accessory Commands

Command Categories

Range Category Example Commands
0x00 System Stop (0x00), Go (0x01), Halt (0x02)
0x01-0x0A Management Speed (0x04), Direction (0x05), Function (0x06)
0x0B-0x0D Accessory Turnout control
0x18-0x1C Software PING (0x18), CAN BOOT (0x1B)
0x20-0x22 GUI GUI commands
0x10-0x12 Feedback S88 events (0x11)
0x30-0xFF Automation Automation commands

Improved Readability

Compare the old vs. new approach:

// OLD: Direct array access with magic indices
int speed = m.getElement(9);
speed = (speed << 8) + m.getElement(10);

// NEW: Named methods with clear intent
int speed = (decoded.getDataByte(0) << 8) + decoded.getDataByte(1);

Usage Examples

Decoding Messages (MarklinMon, MarklinThrottle, MarklinTurnout)

@Override
public void reply(MarklinReply m) {
    // Decode using convenience method
    MarklinCanCodec.DecodedMessage decoded = MarklinCanCodec.decode(m);

    // Work with structured data
    if (decoded.getCommand() == MarklinConstants.LOCOSPEED) {
        int speed = (decoded.getDataByte(0) << 8) + decoded.getDataByte(1);
        processSpeed(speed);
    }
}

Encoding Messages (MarklinMessage)

public static MarklinMessage setLocoSpeed(int addr, int speed) {
    int[] encoded = MarklinCanCodec.builder()
        .setCommand(MarklinConstants.LOCOSPEED)
        .setAddress(addr)
        .setData((speed >> 8) & 0xff, speed & 0xff)
        .setDataLength(2)
        .build();
    return new MarklinMessage(encoded);
}

Display Logic (MarklinMon)

private static void appendCommand(MarklinCanCodec.DecodedMessage decoded, StringBuilder sb) {
    sb.append(" Command: ");
    if (decoded.getCommand() == MarklinConstants.LOCOSPEED) {
        int speed = (decoded.getDataByte(0) << 8) + decoded.getDataByte(1);
        sb.append("Change of speed ").append(speed);
    }
    // ...
}

Related Classes

The codec library is the foundation for several higher-level classes that handle protocol formatting, device identification and device management.

MarklinMessageFormatter

Formats raw MCAN frames for display and logging. Used by both JMRI's MarklinMon monitor pane and the standalone MCAN TCP Bridge monitor mode.

// Format a raw frame with device identification
String text = MarklinMessageFormatter.formatRaw(rawData, null, true);

// Format directly from raw bytes (standalone, no i18n)
String text = MarklinMessageFormatter.formatRaw(rawData, null);

Output example:

[MS2:0x00112233] Priority 4: Engine/Accessory Command Command: Change of speed 512 Request to Loco Address 3 0x5, 0x9, 0x47, 0x11, 0x2, 0x0, 0x0, 0x0, 0x3, 0x2, 0x0, 0x0, 0x0

An optional I18nProvider interface allows JMRI to supply localized strings while the same class works without JMRI runtime in the bridge.

MarklinDeviceIdentifier

Identifies Märklin CAN devices from protocol messages. Supports passive identification from PING responses (command 0x18) and partial fingerprinting from hash bytes in ordinary traffic.

// From a PING response (DLC=8): returns full DeviceInfo with UID, type, SW version
MarklinDeviceIdentifier.DeviceInfo info = MarklinDeviceIdentifier.fromPingResponse(decoded);

// From any message hash: returns DeviceInfo with hash only
MarklinDeviceIdentifier.DeviceInfo info = MarklinDeviceIdentifier.fromHash(decoded);

// Compact string for logging: "[MS2:0x00112233]" or "[Hash:0xABCD]"
String label = MarklinDeviceIdentifier.formatCompact(info);

McanDevice and McanDeviceState

McanDevice is a JMRI NamedBean representing one device on the MCAN bus. It tracks the device identity, software version, hardware version, first-seen and last-seen timestamps and a lifecycle state.

Lifecycle states (McanDeviceState):

StateMeaning
DISCOVEREDPing reply received; identity established
INITIALIZINGFollow-up parameter reads in progress
ONLINEFully initialized and actively responding
STALENo response within configured threshold
OFFLINEExplicitly disconnected or lost

Property change events are dispatched on the Swing EDT for thread safety.

McanDeviceIdentity

Immutable identity for an MCAN device. Has two concrete subtypes:

  • McanDeviceIdentity.Native - identified by 32-bit UID and 16-bit device type (e.g. CS2, MS2, Gleisbox). System name fragment: uid-00112233.
  • McanDeviceIdentity.CdB - identified by CAN class and module ID (CAN-digital-bahn modules). System name fragment: cdb-22-03.
McanDeviceIdentity.Native nat = McanDeviceIdentity.forNative(0x00112233L, 0x0030);
// nat.getSystemName("M") == "M:dev:uid-00112233"

McanDeviceIdentity.CdB cdb = McanDeviceIdentity.forCdB(0x22, 3);
// cdb.getSystemName("M") == "M:dev:cdb-22-03"

McanDeviceManager

McanDeviceManager is a JMRI AbstractManager that discovers and tracks all MCAN devices seen on the bus. It listens to both native MCAN messages (via MarklinListener) and CdB configuration frames (via CdBConfigListener).

// Discover native Marklin devices (CS2, MS2, Gleisbox, CC-Schnitte)
manager.discoverMarklinDevices();

// Discover all known CdB device classes
manager.discoverAllCdBDevices();

// Discover one specific CdB class
manager.discoverCdBDevice(CdBDeviceClass.WEICHEN_CHEF_MAGNET);

Here CdBDeviceClass is jmri.jmrix.marklin.mcan.device.CdBDeviceClass.

CdBMessage

Factory for CAN-digital-bahn (CdB) configuration frames. Builds raw 13-byte frames using MarklinCanCodec.builder() without requiring a JMRI runtime.

// General CdB ping
int[] frame = CdBMessage.createPing(hash);

// Class-specific zero-DLC discovery ping
int[] frame = CdBMessage.createClassPing(CdBMessage.CdBDeviceClass.GLEIS_REPORTER);

// Read a parameter from a specific module
int[] frame = CdBMessage.createReadParam(0x22, 3, paramIndex, hash);

// Write a parameter
int[] frame = CdBMessage.createWriteParam(0x22, 3, paramIndex, value, hash);

CdBMessage.createClassPing uses the nested CdBMessage.CdBDeviceClass enum. Device discovery uses jmri.jmrix.marklin.mcan.device.CdBDeviceClass:
