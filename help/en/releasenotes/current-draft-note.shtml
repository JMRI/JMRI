CBUS

  • CBUS sensor, turnout and light addresses: an unsigned address such as 100001 is treated the same as +100001, node numbers of 21475 and above no longer overflow, and an out of range address is reported as invalid instead of throwing an exception.
  • CBUS programming reports a busy command station or a CV error straight away, instead of waiting for the programming timeout.
  • The CANCMD node variable editor shows and writes the current limits as the raw values the CANCMD firmware uses, writes the walkabout timeout from its own control, and opens for modules whose settings are outside the previous limited ranges.
  • Closing the CBUS bootloader window stops all of its timers, and the fast write speed choice is now saved.
  • The CBUS bootloader only accepts parameter replies from the module being programmed, for the parameter it asked for, and the module device ID is shown correctly.
  • CBUS performance on busy layouts: incoming frames are dispatched to sensors, turnouts and lights with much less work and no per-frame garbage, and the Event Table and Console do far less work for each frame.
  • CBUS Node Manager: teaching events now completes on modules which only accept changes in learn mode (eg. CANSERVO8C, CANMIO-SVO); an EVLRNI reply no longer throws an exception; an aborted NV fetch no longer leaves the node permanently unread; events invalidated after a failed fetch are read again; enumerating CAN IDs no longer resets an existing node; a node no longer shows JMRI's own CAN ID; and reading the events of a node with many events is faster.
  • The CBUS fast clock uses the calendar year rather than the week-based year, accepts and sends temperatures from -128 to 127 correctly, and stops listening to the JMRI clock when it is disposed. CBUS consist listeners are no longer shared between connections.
  • CBUS windows: the Node Manager releases all of its tabs when closed, NV edit windows are no longer bound to the first node they were opened for, the Console closes its log file when closed and shows when a log file could not be opened, and the SPROG 3 Plus CAN disable setting is shown instead of being greyed out.
  • CBUS throttles: a released throttle is removed from the session list, so an emergency stop reaches every remaining throttle instead of failing partway through; after a command station reset a recovered session is only given back to the throttle for the same loco; and nothing is sent to the layout while a throttle has no session, where previously a speed or function change could go out with an invalid session.
  • A CBUS reporter set to Classic RFID always decodes 5 byte tags as Classic RFID, whatever the first tag byte, and an existing reporter's type is never changed by the frames it receives. A reporter created by a CANRCOM RailCom report is still set to the self-describing type automatically.
  • The CBUS bootloader checks a hex file before it can be used. The Program button stays disabled until the file has been read without error and its parameters checked; a file with record types the bootloader does not understand is rejected; the MERG parameter block checksum is now verified; and a load address missing from the file stops programming cleanly instead of throwing an exception. The hex file is closed after reading instead of being left open and locked, and short records are padded correctly for the AN247 bootloader.
  • Unplugging a CANUSB4 or other GridConnect USB adapter on Windows no longer leaves JMRI running a CPU core flat out; the connection fails and reconnects when the adapter is plugged back in. Closing a connection no longer replays the last frame received.
  • GridConnect connections (CANUSB, CANUSB4, CANRS and LCC GridConnect adapters): when the ';' ending a frame is lost, the next frame is now received instead of both being merged into one corrupt frame; and corrupt frames are dropped instead of being passed on as events.
  • CAN connections: a frame received from the layout is no longer also delivered to whichever tool sent the last frame, so a tool window which has been closed stops receiving traffic.
  • CBUS Reporters with erase-on-timeout: reading the same tag again restarts the timeout, so a tag still being read is no longer cleared early.

Dispatcher

  • An automatic "Head and Tail" train with no stopping sensor and no speed profile stopping can now draw fully into a Section before stopping, by watching the Block holding its tail go unoccupied, as an "Entire Train" train does. Previously it stopped as soon as the locomotive entered the Section.
  • When the maximum speed of an automatically running train is entered as a scale speed (scale mph or scale km/h), that limit is now applied as entered. Previously it could be reduced by the stored throttle percentage value in the Physics ramp and in distance-based stopping. The throttle percentage is now only a fallback for locomotives without a speed profile, or when the profile does not cover the direction of travel; a warning is written to the system console in that case.
  • The scale speed conversions for the maximum speed and the scale speed shown for the minimum throttle now follow the "Run in reverse" setting, and the scale km/h entry is no longer labelled as scale mph.
  • Fix TSA Go to Manual and Resume from Manual.
  • Automatic release of Sections no longer releases a Section when the next Section has not been entered, or when the train is stopped, waiting or in manual mode.
  • Trains using "Head Only" or "Head and Tail" train detection must now have a Max Train Length, whether or not they run automatically. A train without one is refused when it is added or loaded, with a message saying why. The Max Train Length field is now shown for these trains even when they do not run automatically.
  • Sections behind a "Head Only" train are now released using the train length for every train, not only automatic ones. Previously a dispatched or manual "Head Only" train had each Section released as soon as the locomotive left it.
  • For a "Head and Tail" train a Section is now released using the train length, measured to the head, as for a "Head Only" train. Previously, if the tail lost detection, for example through dirty wheels, Sections could be released while the train was still in them, all the way up to the head.
  • An automatic train's speed ramp no longer carries on after the train is halted, and a new ramp no longer runs alongside an old one when the speed is changed quickly.
  • An automatic train now always finds the correct next Block in its Section. Before, block or signal changes at the same moment could give it the wrong Block or none. Reversing or resetting a train that fills its Section no longer fails.
  • Restarting a train no longer starts allocating before the release of its old Sections has finished, and no longer freezes the screen while it waits. A second Restart of a train that is already being reset is ignored.
  • Automatic release of Sections is faster when many Sections are allocated, as each check now goes through the allocated Sections once. Which Sections are released is unchanged.
  • When an automatic train's stop is cancelled, for example because the signal clears or an allocation arrives, its end, reversal or reset action is now dropped too. Before, it could run later, wherever the train next stopped.
  • An automatic train's Block changes are now handled one at a time, in the order they happen. Before, each change was handled separately, so a train entering two Blocks in quick succession could be stopped for entering a Block out of turn, a short Block crossed at speed could be missed, and a train could be stopped with "No next Block". Every change is now acted on, including a detector that bounces, so use the sensor debounce settings for such detectors.

Layout Editor

  • With advanced block routing on, through paths whose turnouts were already set when routing started, for example after the start-up state query, are now marked active, so routes through them are found. A route is no longer marked invalid while another active path in the block still uses it, and removed routes and through paths stop listening to their block and turnouts.
  • With advanced block routing on, a block now sends a routing update to its neighbours only when its status (occupied, reserved, empty or unknown) changes, not on every change to the block such as a new reporter value. This reduces the work done on large layouts.
  • Finding the Layout Block for a Block no longer searches every Layout Block each time. This speeds up advanced block routing, Signal Mast Logic, Dispatcher and Entry/Exit on large layouts.
  • With advanced block routing on, the shortest route to a destination is now found when it is the first or only route, so changes to block lengths are passed on through the layout.
  • With advanced block routing on, when two routes to a destination are equally good, the same one is now always chosen: the one with fewer blocks, then by the name of the next block. Before, the choice could change after an unrelated edit to the layout.
  • Layout Editor block routing: the path search now finds routes that exist when the preferred branch has two or more dead-end or occupied sub-branches. Before, NX, Dispatcher ad-hoc routes and Signal Mast Logic could report "no route" in these cases.
  • An allocated block, that is one set to use its extra color, for example by the LogixNG Block action "Alternate Color On" or by a script, now keeps its extra color until it is turned off, for example by the LogixNG Block action "Alternate Color Off". The LogixNG Block expression "Is Allocated" tests this. Before, with advanced block routing on, the block was switched back to its normal color without notice as soon as it became occupied. LogixNG and scripts that set it must now also clear it, for example when the train has left. Dispatcher and Entry/Exit are not affected: they clear their own blocks.

NX - Entry/Exit Tool

  • NX with signal masts: if a train enters the start block while the route is still being set, the first block of the route stays protected. Before, it was dropped and the entry signal could stay clear behind the train.
  • NX: when a train reaches a block of a route without being seen in the block before it, that block now keeps the value it already has, for example from RFID, and is only given the train's value if it has none. A block that is not part of the route is no longer changed. Block values further along a route might therefore differ from earlier versions.
  • NX: a route made up of several Entry/Exit pairs now sets every pair, one after the other. Before, it could stop after the first pair unless that pair used full interlocking, and the remaining pairs were then set by the next, unrelated request.
  • The Revert to the old GUI behavioroption has been removed. Double clicking on the destination sensor will complete the NX pair and start the process for the next NX pair to extend the route.

LccPro

  • Added a new item to the popup menu on a node line: Refresh Node Info. This lets you update the info on that line from the node without refreshing the entire table (which can take a while for large networks)

Logix

  • Logix: a deleted Logix now stops running. Before, deleting an enabled Logix left it setting turnouts and sensors until JMRI was restarted. This includes a Logix that was loaded disabled and enabled later, which could not be stopped this way even where the delete did deactivate it.
  • Logix: Logixes whose actions trigger each other in an endless loop are now stopped, and an error names the Conditionals in the loop. Before, the loop ran until Java's stack overflowed, and other listeners on the sensor or turnout that started it were skipped. A loop through so many Logixes that the stack still overflows first now logs where it started.

LogixNG

  • LogixNG formulas: comparing a decimal value with a whole number now gives the right answer. Before, 1.5 == 2 was true and 2.5 < 3 was false.
  • LogixNG Block, Section and Transit expressions now only run their ConditionalNG when a property they can test changes (block state, value and allocation; section state and occupancy; transit state), not on every change of the bean, for example each time a Reporter writes a new value into a Block. A ConditionalNG that relied on running for other changes of these beans will now run less often.
  • LogixNG formulas: the && and || operators now only evaluate the right-hand side when the left-hand side does not already decide the result, as in most programming languages. This lets a check guard what follows it, for example (x != null) && (x.y == 1). A formula that relied on both sides always being evaluated, to call methods for their side effects, must be changed. For example, myArray.add("Hello") || myArray.add(" ") || myArray.add("World!") now only adds "Hello": add returns true, so || has its answer after the first call and skips the rest. Use myArray.add("Hello") && myArray.add(" ") && myArray.add("World!") instead, which carries on while each call returns true.

Signal Masts

  • A Signal Mast Logic mast now goes to danger as soon as a block on its route becomes occupied, instead of first waiting for the signal logic delay; changes back towards clear are still delayed as before.
  • Generating Signal Mast Logic Sections no longer stops at the first Source:Destination pair whose Section name is already used by a user-defined Section: only that pair is skipped. A user-defined Section also keeps its forward mast.
  • Signal Mast Logic now only sends an aspect to its source mast when the aspect changes. Before, every re-check of the logic, for example when a block or turnout changed on any route from the mast, sent the same aspect again, giving extra traffic on the layout and a brief flicker on masts set to reset previous states. A mast whose hardware has lost its aspect, for example after a power cycle, now keeps its old output until the aspect next changes.
  • A Signal Mast Logic mast keeps following its logic if setting its held aspect fails. Before, it stopped changing until JMRI was restarted. If the held aspect is disabled for the mast, the danger aspect is used instead.
  • When Signal Mast Logic starts, it now uses the same route checks as when a block, turnout or mast changes. Before, a user-set mast overriding an automatic one was tested the wrong way round, blocks set to "any state" always failed and Dispatcher reservations were ignored until the first change. Starting the logic again no longer adds its listeners twice.
  • Turning off "Use Layout Editor Paths" for one destination of a source mast no longer stops Signal Mast Logic Sections being generated for that mast's other destinations.

Turnouts, Lights, Sensors and other elements

  • Turnouts with DELAYED feedback no longer flip back to an earlier position when two commands are given within the feedback delay, including CBUS turnouts changed by events on the bus, and turnout commands spaced by the connection's output interval (Routes, Dispatcher, matrix signal masts) are always sent in the order requested.
  • Editing a turnout's automation settings from the "Edit Auto" button in the Turnout Table or the Feedback tab of the Edit Turnout window now actually saves the change. Previously, if the turnout's automation was set to a named operation (rather than "Default"), the edit landed on a disconnected copy and the turnout kept using its old settings. The automation dropdown also now shows the right type (for example "Raw") for a turnout with its own settings, instead of always showing the first one.
  • A turnout with its own custom automation settings now keeps automation turned on after the panel file is reloaded. Previously it came back with automation off, and saving again replaced the custom settings with "Off".

Warrants

  • A number of bug fixes have been made to Warrants. If this causes problems for you, you can ask for support on the JMRI users list. The changes are:
  • Warrants: a "Wait Sensor" command in a warrant script now holds the train until the sensor really reaches the requested state; before, the train could leave early when a signal cleared, a train ahead moved on, or a speed change finished. Resume, Increase Speed and Move into next block still release a train held at a sensor, so the operator can get past a sensor that has failed.
  • A delayed speed change that replaces an earlier one can now be cancelled, and a cancelled one stops at once.
  • A slow-down or stop is no longer sometimes missed. An error while a warrant runs now stops the train and the warrant. Script function commands can use all the functions of the throttle, not only F0 to F28.
  • A warrant no longer moves its train on when a block further ahead becomes occupied while a detected block in between is still empty.
  • A planned slow-down in a script now starts at the right time. Before, it could start late, or at once after a Speed 0 command.
  • Each change of an OBlock is now reported once, not twice, to track icons, Tracker, warrants and the Web Server.
  • The Stop button of the route search now stops the search and shows the routes found so far. Pressing Calculate again cancels the search still running.
  • A signal controlled (SCWarrant) train waiting for its next block no longer adds another listener to that block every few seconds.
  • A speed measured during a warrant run is now merged once into the speed profile. The first measurement for a direction is no longer halved.
